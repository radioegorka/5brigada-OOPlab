# ЛР1. Запрос авторизации как объект

Вариант: **Authorization**.

## Что дано

Процедурная реализация выбирает первый отказ во входном порядке. Все тесты проходят.

## Задание

Создайте `AuthorizationRequest` и `AuthorizationService`. Готовый объект результата используйте без изменений.

Добавьте `request.failed_checks()`: метод возвращает отказавшие проверки в исходном порядке. Сервис должен обрабатывать объект запроса. Пока достаточно одного алгоритма без абстрактного класса.

## Примеры и границы

- Шесть разрешений дают `APPROVED`.
- Единственный отказ `FUNDS` даёт `DECLINED` с причиной `INSUFFICIENT_FUNDS`.
- Разрешённый запрос после отклонённого проходит; предыдущая причина не переносится.
- Исходная коллекция `checks` не меняется.

Все проверки открыты: `tests/test_contract.py` и `tests/test_review_contract.py`.
Описание объектов — в [REFERENCE.md](REFERENCE.md), исходные результаты тестов — в [STARTER-STATE.md](STARTER-STATE.md).

## Разрешённые файлы

- `app/domain/authorization.py`
- `app/services/authorization_service.py`

`app/api.py`, `app/support/`, тесты и файлы запуска не меняйте. До ЛР5 файл `app/services/assembly.py` также остаётся без изменений.

Покажите экземпляр запроса и его обработку сервисом. Объясните, где хранятся результаты проверок и почему авторизация не меняет баланс.

Работа сдана, когда все обязательные тесты проходят, изменения из задания выполнены,
а оба участника внесли содержательные коммиты и могут объяснить решение.
